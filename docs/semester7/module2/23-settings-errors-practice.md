# 23. (П12) Налаштування застосунку та обробка помилок

## Мета роботи

- **Освітня (навчальна):** навчитися зберігати й відновлювати налаштування застосунку через `QSettings` і файли JSON/INI, обробляти помилки на всіх рівнях застосунку та вести журнал роботи модулем `logging`.
- **Дослідна (розвиваюча):** розвинути вміння передбачати відсутні, пошкоджені або застарілі налаштування й забезпечувати роботу застосунку в будь-якому з цих випадків.
- **Виховна (патріотична):** сформувати повагу до вибору користувача та відповідальність за стабільність програми, якою людина користується щодня.

!!! danger "Персоналізація обовʼязкова"
    Налаштування зберігаються для **вашого** застосунку з назвою організації — вашим прізвищем (`QSettings("petrenko", "ExpenseTracker")`).

## Підготовка

Скористайтеся `expense_tracker` з роботи П11. Перегляньте [лекцію про логування](../../semester5/module3/26-logging-lecture.md) з 5 семестру.

## Хід роботи

### Завдання 1. Розмір і положення вікна

```python
from PySide6.QtCore import QSettings

settings = QSettings("petrenko", "ExpenseTracker")
settings.setValue("window/size", [900, 600])
print(settings.fileName())
print(settings.value("window/size"))
```

У головному вікні збережіть геометрію (`saveGeometry`) і стан панелей (`saveState`) під час закриття та відновіть під час запуску.

**Очікуваний результат:** після перезапуску вікно відкривається з тим самим розміром, положенням і розташуванням док-панелі; у звіті шлях до файлу налаштувань у вашій системі.

### Завдання 2. Налаштування користувача

Збережіть налаштування з вікна `Settings` (робота П9): бюджет, валюта, папка з даними, останній відкритий файл. Під час запуску застосунок відкриває останній файл.

**Очікуваний результат:** після перезапуску застосунок відновлює всі налаштування; якщо останнього файлу вже немає — відкривається порожній список з повідомленням у рядку стану.

### Завдання 3. Експорт та імпорт налаштувань

Додайте дії `Export settings...` (у JSON) і `Import settings...`. Імпорт перевіряє типи й допустимі значення; пошкоджений файл не змінює поточних налаштувань.

**Очікуваний результат:** налаштування можна перенести на інший компʼютер, а пошкоджений JSON дає повідомлення без зміни поточного стану.

### Завдання 4. Журнал і перехоплення помилок

1. Налаштуйте `logging` із записом у файл `expense_tracker.log` у каталозі даних застосунку.
2. Встановіть `sys.excepthook`, що записує неперехоплений виняток у журнал і показує `QMessageBox.critical` з коротким повідомленням.
3. Додайте пункт меню `Help → Simulate error`, що генерує `RuntimeError`.

**Очікуваний результат:** після «помилки» застосунок показує повідомлення, а повне трасування є в журналі.
