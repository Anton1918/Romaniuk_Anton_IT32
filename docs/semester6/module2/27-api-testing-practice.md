# 27. (П13) Тестування REST API за допомогою pytest

## Мета роботи

- **Освітня (навчальна):** навчитися тестувати REST API тестовим клієнтом Flask і `pytest`: перевіряти коди стану, JSON-відповіді, заголовки, роботу сесій і помилкові сценарії.
- **Дослідна (розвиваюча):** розвинути вміння складати набір тестів за специфікацією API і оцінювати повноту перевірки.
- **Виховна (патріотична):** сформувати відповідальність за якість сервісів, якими користуються люди: кожна зміна коду має бути перевірена автоматично.

!!! danger "Персоналізація обовʼязкова"
    Тести перевіряють **ваш** API з робіт П11–П12, а тестові дані — ваші реальні задачі.

## Підготовка

Скопіюйте `lab12_sessions` у `lab13_api_tests`. Встановіть `pytest`. Перетворіть створення застосунку на фабрику `create_app(config)`, щоб тести могли підключати тестову базу `tasks_<прізвище>_test`.

## Хід роботи

### Завдання 1. Фікстури

Файл `tests/conftest.py` містить фікстури:

1. `app` — застосунок з тестовою конфігурацією (`TESTING=True`, тестова база).
2. `client` — `app.test_client()`.
3. `auth_client` — клієнт, що вже увійшов як тестовий користувач.

**Очікуваний результат:** фікстури очищують таблиці після кожного тесту, тести можна запускати в будь-якому порядку.

### Завдання 2. Позитивні сценарії

```python
def test_create_task(auth_client):
    response = auth_client.post(
        "/tasks",
        json={"title": "Practice 13: API tests", "subject": "Programming"},
    )
    assert response.status_code == 201
    task = response.get_json()
    assert task["title"] == "Practice 13: API tests"
    assert task["status"] == "todo"
```

Напишіть тести для отримання списку, однієї задачі, оновлення і видалення.

**Очікуваний результат:** щонайменше 5 тестів, кожен перевіряє і код стану, і вміст відповіді.

### Завдання 3. Помилкові сценарії

Напишіть тести для кодів `400` (некоректні дані — параметризуйте 4 варіанти), `401` (без входу), `404` (неіснуюча й чужа задача) і `405` (непідтримуваний метод).

**Очікуваний результат:** для кожного коду помилки є щонайменше один тест; параметризований тест показує 4 окремі запуски.

### Завдання 4. Покриття

Встановіть `pytest-cov` і виконайте `pytest --cov=. --cov-report=term-missing`. Знайдіть непокриті рядки і допишіть тести, щоб покриття маршрутів було не менше 85 %.

**Очікуваний результат:** у звіті два виводи покриття — до і після доповнення тестів.
