# 23. (П11) CRUD-операції REST API та робота з базою даних у Flask

## Мета роботи

- **Освітня (навчальна):** навчитися зберігати дані REST API у PostgreSQL, реалізувати повний набір CRUD-маршрутів і відокремлювати код доступу до даних від маршрутів.
- **Дослідна (розвиваюча):** розвинути вміння перетворювати помилки бази даних на коректні HTTP-відповіді та перевіряти узгодженість API з його специфікацією.
- **Виховна (патріотична):** сформувати відповідальність за цілісність даних, що надходять від користувачів сервісу.

!!! danger "Персоналізація обовʼязкова"
    База `tasks_<прізвище>` містить **ваші** реальні навчальні задачі цього семестру.

## Підготовка

1. Скопіюйте `lab10_request_data` у `lab11_crud`. Встановіть `psycopg2-binary`.
2. Створіть базу `tasks_<прізвище>` (у контейнері з роботи П7 або локально).
3. Структура проєкту:

    ```text
    lab11_crud/
      app.py          # маршрути
      db.py           # підключення
      repository.py   # SQL-запити
      schema.sql
    ```

## Хід роботи

### Завдання 1. Схема і підключення

Файл `schema.sql` — таблиця `tasks` за вашою специфікацією з роботи П8. Файл `db.py` — функція `get_conn()`, що створює підключення один раз на запит і зберігає його в `flask.g`, та функція закриття, зареєстрована через `app.teardown_appcontext`.

**Очікуваний результат:** кожен HTTP-запит використовує одне підключення, яке закривається після відповіді (перевірте виводом у журнал).

### Завдання 2. Маршрути CRUD

Реалізуйте всі маршрути, використовуючи функції з `repository.py`:

| Метод | URL | Код |
|---|---|---|
| `GET` | `/tasks` | `200` |
| `GET` | `/tasks/<id>` | `200` / `404` |
| `POST` | `/tasks` | `201` / `400` |
| `PUT` | `/tasks/<id>` | `200` / `400` / `404` |
| `PATCH` | `/tasks/<id>` | `200` / `400` / `404` |
| `DELETE` | `/tasks/<id>` | `204` / `404` |

Вставка повертає створений рядок через `RETURNING`.

**Очікуваний результат:** після перезапуску сервера задачі зберігаються; дати у відповіді мають формат `YYYY-MM-DD`.

### Завдання 3. Помилки бази даних

Додайте обробник помилок, що перетворює `psycopg2.errors.CheckViolation` і `psycopg2.errors.NotNullViolation` на відповідь `400`, а будь-яку іншу помилку бази — на `500` з загальним повідомленням (без подробиць SQL у відповіді).

**Очікуваний результат:** клієнт ніколи не бачить тексту SQL-помилки, а в журналі сервера вона записана повністю.

### Завдання 4. Перевірка за специфікацією

Виконайте всі приклади запитів з вашого `API.md` (робота П8) і порівняйте відповіді з очікуваними. Виправте розбіжності у коді або в специфікації.

**Очікуваний результат:** у звіті таблиця «запит — очікувана відповідь — фактична відповідь» без розбіжностей.
