## Хід роботи

### Завдання 1. Реєстрація

Маршрут `POST /register` приймає `name`, `email`, `password`, перевіряє довжину пароля (не менше 8 символів) і зберігає **хеш** пароля.

**Очікуваний результат:** у таблиці `users` немає паролів у відкритому вигляді; повторна реєстрація з тим самим email повертає `409`.

### Завдання 2. Вхід і вихід

```python
import os

from flask import Flask, jsonify, request, session
from werkzeug.security import check_password_hash, generate_password_hash

app = Flask(__name__)
app.secret_key = os.environ["SECRET_KEY"]

# у роботі користувачі зберігаються в таблиці users, тут — словник для прикладу
USERS = {
    "ivan.petrenko@example.com": {
        "id": 1,
        "name": "Ivan Petrenko",
        "password_hash": generate_password_hash("change-me-123"),
    },
}


@app.post("/login")
def login():
    data = request.get_json(silent=True) or {}
    user = USERS.get(data.get("email"))
    password = data.get("password", "")
    if user is None or not check_password_hash(user["password_hash"], password):
        return jsonify({"error": "wrong email or password"}), 401
    session["user_id"] = user["id"]
    return jsonify({"name": user["name"]})


@app.post("/logout")
def logout():
    session.clear()
    return "", 204


if __name__ == "__main__":
    app.run(debug=True)
```

У своєму проєкті замініть словник `USERS` функцією пошуку користувача за email у `repository.py`.

**Очікуваний результат:** після входу в браузері зʼявляється cookie `session`, після виходу — зникає; неправильний пароль і неіснуючий email дають однакове повідомлення.

### Завдання 3. Захищені маршрути

Створіть декоратор `login_required`, що повертає `401` для неавторизованого користувача. Застосуйте його до всіх маршрутів `/tasks`. Кожен користувач бачить і змінює лише свої задачі (`WHERE owner_id = %s`).

**Очікуваний результат:** спроба отримати чужу задачу за її `id` повертає `404`, а не саму задачу.

### Завдання 4. Дослідження cookie

1. Перегляньте cookie `session` в інструментах розробника браузера.
2. Декодуйте її першу частину (base64) і поясніть, що в ній видно.
3. Змініть один символ cookie і повторіть запит.

**Очікуваний результат:** у звіті пояснено, чому дані сесії можна прочитати, але не можна підробити, і чому в сесії не можна зберігати пароль.
