# 17. (П8) Проєктування REST API для системи управління задачами

## Мета роботи

- **Освітня (навчальна):** навчитися проєктувати REST API: виділяти ресурси, будувати URL, обирати методи HTTP і коди стану відповіді, описувати формат запитів і відповідей у JSON.
- **Дослідна (розвиваюча):** розвинути вміння аналізувати чуже API, порівнювати його з власним проєктом і обґрунтовувати проєктні рішення.
- **Виховна (патріотична):** сформувати прагнення створювати зручні й зрозумілі сервіси, як-от відкриті API державних систем, якими можуть користуватися інші розробники.

!!! danger "Персоналізація обовʼязкова"
    API описує **ваші** реальні навчальні задачі: здачу практичних, курсових, підготовку до заліків з ваших дисциплін цього семестру.

## Підготовка

Створіть каталог `lab08_api_design` і файл `API.md`, у якому ви оформите проєкт. Цей проєкт ви реалізуєте в роботах П9–П15.

## Хід роботи

### Завдання 1. Ресурси та їхні поля

Опишіть три ресурси системи і поля кожного з типами та обмеженнями:

| Ресурс | Поля |
|---|---|
| `users` | `id`, `name`, `group`, `email` |
| `tasks` | `id`, `title`, `subject`, `due_date`, `status` (`todo`, `in_progress`, `done`), `owner_id` |
| `comments` | `id`, `task_id`, `text`, `created_at` |

**Очікуваний результат:** для кожного поля вказано тип, чи обовʼязкове воно і допустимі значення.

### Завдання 2. Таблиця маршрутів

Складіть таблицю всіх маршрутів API:

| Метод | URL | Дія | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET` | `/tasks` | список задач | `200` | — |
| `POST` | `/tasks` | створити задачу | `201` | `400` |
| `GET` | `/tasks/<id>` | одна задача | `200` | `404` |
| … | … | … | … | … |

Додайте маршрути для оновлення (`PUT`, `PATCH`), видалення (`DELETE`), коментарів задачі (`/tasks/<id>/comments`) і фільтрації (`/tasks?status=todo&subject=Programming`).

**Очікуваний результат:** у таблиці щонайменше 10 маршрутів; URL містять іменники, а не дієслова (`/tasks`, а не `/getTasks`).

### Завдання 3. Приклади запитів і відповідей

Для створення задачі, отримання списку та помилки валідації запишіть приклади тіла запиту й відповіді у JSON. Використайте **ваші** реальні задачі:

```json
{
  "title": "Practice 8: REST API design",
  "subject": "Programming",
  "due_date": "2026-10-27",
  "status": "todo"
}
```

**Очікуваний результат:** приклади містять ваші задачі, а відповідь з помилкою має зрозумілу структуру (`{"error": "...", "field": "..."}`).

### Завдання 4. Аналіз відкритого API

Відкрийте документацію API НБУ або GitHub REST API і знайдіть у ній три рішення, схожі на ваші, та одне, яке ви зробили б інакше. Обґрунтуйте.

**Очікуваний результат:** у звіті чотири пункти порівняння з посиланнями на документацію.
