# 31. (П15) Розгортання Flask REST API у Docker

## Мета роботи

- **Освітня (навчальна):** навчитися створювати `Dockerfile` для застосунку Flask, запускати його через WSGI-сервер gunicorn, передавати конфігурацію змінними середовища та запускати застосунок разом з PostgreSQL за допомогою Docker Compose.
- **Дослідна (розвиваюча):** розвинути вміння оптимізувати образ (кешування шарів, розмір, `.dockerignore`) і вимірювати результат оптимізації.
- **Виховна (патріотична):** сформувати відповідальність за надійність сервісів, що працюють для людей безперервно.

!!! danger "Персоналізація обовʼязкова"
    Образ і контейнери мають ваше прізвище в назві, а застосунок — **ваш** API з робіт П11–П14.

## Підготовка

Скопіюйте проєкт з роботи П14 у `lab15_flask_docker`. Додайте `gunicorn` у `requirements.txt`.

## Хід роботи

### Завдання 1. Dockerfile

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["gunicorn", "--bind", "0.0.0.0:8000", "app:create_app()"]
```

Зберіть образ `petrenko-tasks-api` і запустіть контейнер з перенаправленням порту `8000` і змінними середовища для бази та `SECRET_KEY` (параметри `-e` або `--env-file`).

**Очікуваний результат:** `curl http://localhost:8000/health` повертає `{"status": "ok"}`, а журнал контейнера показує запуск gunicorn.

### Завдання 2. Кешування шарів і .dockerignore

1. Змініть один рядок коду і зберіть образ знову: зафіксуйте, які кроки взято з кешу.
2. Поміняйте місцями `COPY . .` і встановлення залежностей і повторіть — порівняйте час збирання.
3. Створіть `.dockerignore` (`.venv`, `.git`, `__pycache__`, `tests`) і порівняйте розмір образу (`docker images`).

**Очікуваний результат:** у звіті таблиця «варіант — час збирання — розмір образу» і пояснення, чому порядок інструкцій важливий.

### Завдання 3. Docker Compose

Файл `compose.yaml` запускає два сервіси — `db` (PostgreSQL з томом і скриптом ініціалізації) та `api` (ваш образ), де `api` залежить від `db`:

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: tasks
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./schema.sql:/docker-entrypoint-initdb.d/schema.sql
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      PGHOST: db
      PGDATABASE: tasks
      PGUSER: postgres
      PGPASSWORD: ${DB_PASSWORD}
      SECRET_KEY: ${SECRET_KEY}
    depends_on:
      - db

volumes:
  pgdata:
```

Значення змінних зберігаються у файлі `.env`, що не додається до репозиторію.

**Очікуваний результат:** команда `docker compose up --build` запускає обидва сервіси, а API працює з базою в контейнері `db`.

### Завдання 4. Перевірка роботи

Виконайте всі запити з вашого `requests.sh` до API в контейнері (порт `8000`) і запустіть тести з роботи П13 проти цього розгортання.

**Очікуваний результат:** усі запити дають очікувані відповіді; після `docker compose down` і повторного `up` дані збереглися завдяки тому `pgdata`.
