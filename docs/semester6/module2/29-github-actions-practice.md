# 29. (П14) GitHub Actions: автоматичне тестування Python-застосунку

## Мета роботи

- **Освітня (навчальна):** навчитися створювати workflow GitHub Actions, що встановлює залежності, запускає тести з базою PostgreSQL у сервісному контейнері та перевіряє кожен push і pull request.
- **Дослідна (розвиваюча):** розвинути вміння читати журнали виконання workflow і знаходити причину невдалої перевірки.
- **Виховна (патріотична):** сформувати професійну культуру командної розробки, у якій жодна зміна не потрапляє в основну гілку без автоматичної перевірки.

!!! danger "Персоналізація обовʼязкова"
    Workflow запускається у **вашому** публічному репозиторії `tasks-api-<прізвище>` з кодом робіт П11–П13.

## Підготовка

1. Створіть репозиторій `tasks-api-<прізвище>` на GitHub і завантажте в нього код `lab13_api_tests` (без `.venv` і секретів, з `.gitignore`).
2. Переконайтеся, що тести проходять локально.

## Хід роботи

### Завдання 1. Перший workflow

Створіть файл `.github/workflows/tests.yml`:

```yaml
name: tests

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: tasks_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 5s
          --health-retries 10
    env:
      PGHOST: localhost
      PGUSER: postgres
      PGPASSWORD: postgres
      PGDATABASE_TEST: tasks_test
      SECRET_KEY: test-only-secret
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest -v
```

**Очікуваний результат:** на вкладці Actions зʼявився запуск із зеленою позначкою; у журналі видно вивід `pytest -v`.

### Завдання 2. Невдала перевірка

Створіть гілку `broken-test`, навмисно зламайте один маршрут, відкрийте pull request і зафіксуйте червону позначку. Знайдіть у журналі назву тесту, що впав, виправте код і переконайтеся, що перевірка стала зеленою.

**Очікуваний результат:** у звіті знімки pull request з невдалою та успішною перевіркою і рядок журналу з причиною збою.

### Завдання 3. Кілька версій Python

Додайте матрицю версій `3.11`, `3.12`, `3.13` (`strategy.matrix`).

**Очікуваний результат:** workflow виконує три паралельні завдання, по одному на кожну версію.

### Завдання 4. Бейдж і захист гілки

1. Додайте до `README.md` бейдж статусу workflow.
2. У налаштуваннях репозиторію ввімкніть правило для гілки `main`: злиття лише після успішної перевірки.

**Очікуваний результат:** бейдж показує поточний стан тестів, а pull request з невдалою перевіркою неможливо злити.
