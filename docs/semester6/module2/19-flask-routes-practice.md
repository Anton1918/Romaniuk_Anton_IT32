## Мета роботи

- **Дослідна (розвиваюча):** розвинути вміння перевіряти роботу маршрутів різними інструментами (браузер, curl) і читати журнал сервера розробки.
- **Виховна (патріотична):** сформувати культуру послідовної реалізації проєкту за власною специфікацією.

## Підготовка

Створіть каталог `lab09_flask` з віртуальним середовищем і встановіть `flask`. Дані в цій роботі зберігаються у списку в памʼяті; базу даних підключимо в роботі П11.

## Хід роботи

### Завдання 1. Мінімальний застосунок

Файл `app.py`:

```python
from flask import Flask, jsonify

app = Flask(__name__)

TASKS = [
    {"id": 1, "title": "Practice 9: Flask routes", "subject": "Programming", "status": "todo"},
]


@app.get("/health")
def health():
    return jsonify({"status": "ok"})


@app.get("/tasks")
def list_tasks():
    return jsonify(TASKS)


if __name__ == "__main__":
    app.run(debug=True)
```

Замініть приклад задачі на 5 ваших реальних задач. Запустіть застосунок і відкрийте `/health` та `/tasks` у браузері.

**Очікуваний результат:** обидва маршрути повертають JSON, а в журналі сервера видно запити з кодом `200`.

### Завдання 2. Одна задача та 404

Додайте маршрут `GET /tasks/<int:task_id>`. Для неіснуючої задачі поверніть `{"error": "task not found"}` з кодом `404`.

**Очікуваний результат:** `curl -i http://127.0.0.1:5000/tasks/999` показує код `404` і JSON з помилкою; `/tasks/abc` повертає `404`, бо не відповідає конвертеру `int`.

### Завдання 3. Створення та видалення

Додайте маршрути `POST /tasks` (поки що з фіксованими даними, читання тіла запиту — у роботі П10) і `DELETE /tasks/<int:task_id>` з кодом `204`.

**Очікуваний результат:** після `POST` кількість задач у `/tasks` збільшується, після `DELETE` — зменшується; відповідь на `DELETE` не має тіла.

### Завдання 4. Метод не дозволено

Надішліть `PUT /tasks` і `PATCH /health`. Зафіксуйте код відповіді й заголовок `Allow`.

**Очікуваний результат:** обидва запити отримують код `405`, а заголовок `Allow` перелічує дозволені методи.
