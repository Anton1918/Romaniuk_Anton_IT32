# 13. (П6) Встановлення Docker. Базові команди

## Мета роботи

- **Освітня (навчальна):** навчитися встановлювати Docker, завантажувати образи, запускати й зупиняти контейнери та користуватися командами `build`, `run`, `ps`, `stop`, `rm`, `logs`, `exec`.
- **Дослідна (розвиваюча):** розвинути розуміння різниці між образом і контейнером та вміння досліджувати середовище всередині контейнера.
- **Виховна (патріотична):** сформувати культуру відтворюваних технічних рішень: середовище, описане кодом, однаково працює в усіх членів команди.

!!! danger "Персоналізація обовʼязкова"
    Контейнери називаються з вашим прізвищем (`petrenko-web`), а власний образ виводить ваші дані.

## Підготовка

1. Встановіть Docker Engine або Docker Desktop за [офіційною інструкцією](https://docs.docker.com/get-started/get-docker/).
2. Перевірте встановлення: `docker --version` і `docker run hello-world`.
3. Створіть каталог `lab06_docker`.

## Хід роботи

### Завдання 1. Перший контейнер

1. Запустіть `docker run hello-world` і поясніть, які кроки виконав Docker (повідомлення в виводі).
2. Виконайте `docker images` і `docker ps -a`: знайдіть образ і зупинений контейнер.

**Очікуваний результат:** у звіті вивід трьох команд і пояснення, чому контейнер `hello-world` одразу зупинився.

### Завдання 2. Контейнер з вебсервером

1. Запустіть nginx у фоновому режимі з вашою назвою та перенаправленням порту:

    ```bash
    docker run -d --name petrenko-web -p 8080:80 nginx:stable
    ```

2. Відкрийте `http://localhost:8080` у браузері.
3. Перегляньте журнал (`docker logs petrenko-web`) і знайдіть рядок вашого запиту.
4. Зупиніть і видаліть контейнер (`docker stop`, `docker rm`).

**Очікуваний результат:** сторінка nginx відкривається, а в журналі є рядок `GET /` з кодом `200`.

### Завдання 3. Усередині контейнера

1. Запустіть інтерактивний контейнер Python: `docker run -it --rm python:3.12-slim bash`.
2. Виконайте `python --version`, `cat /etc/os-release`, `whoami` і `ls /`.
3. Створіть файл `/tmp/<прізвище>.txt`, вийдіть з контейнера і запустіть його знову. Чи є файл?

**Очікуваний результат:** у звіті пояснено, чому файл зник і що означає параметр `--rm`.

### Завдання 4. Власний образ

Створіть файл `hello.py`, що виводить ваше імʼя, групу і версію Python, та `Dockerfile`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY hello.py .
CMD ["python", "hello.py"]
```

Зберіть образ (`docker build -t petrenko-hello .`) і запустіть його.

```text
$ docker run --rm petrenko-hello
Ivan Petrenko, PZ-11
python 3.12.7
```

**Очікуваний результат:** образ `petrenko-hello` присутній у `docker images`, а контейнер виводить ваші дані.

### Завдання 5. Команда exec

Запустіть контейнер nginx знову і за допомогою `docker exec` замініть стартову сторінку на власну (`/usr/share/nginx/html/index.html` з вашим імʼям і групою). Оновіть сторінку в браузері.

**Очікуваний результат:** браузер показує вашу сторінку; після перезапуску нового контейнера з образу nginx сторінка знову стандартна — поясніть чому.
