# 15. (П7) PostgreSQL у Docker-контейнері: тестові дані та збереження

## Мета роботи

- **Освітня (навчальна):** навчитися запускати PostgreSQL у Docker-контейнері зі змінними середовища, перенаправленням порту та іменованим томом, наповнювати базу тестовими даними й підключатися до неї з Python.
- **Дослідна (розвиваюча):** розвинути вміння перевіряти, де контейнер зберігає дані і що з ними стається після його видалення.
- **Виховна (патріотична):** сформувати відповідальне ставлення до збереження даних і резервного копіювання як складової стійкості інформаційних систем.

!!! danger "Персоналізація обовʼязкова"
    Контейнер, том і база названі вашим прізвищем, а база наповнюється вашими витратами з робіт П1–П3.

## Підготовка

Створіть каталог `lab07_docker_db`. Знадобляться Docker (робота П6) і середовище з `psycopg2-binary` (робота П2).

## Хід роботи

### Завдання 1. Запуск PostgreSQL з томом

```bash
docker volume create petrenko-pgdata
docker run -d --name petrenko-db \
    -e POSTGRES_PASSWORD=secret \
    -e POSTGRES_DB=expenses_petrenko \
    -p 5433:5432 \
    -v petrenko-pgdata:/var/lib/postgresql/data \
    postgres:16
```

Перевірте журнал (`docker logs petrenko-db`) і знайдіть повідомлення про готовність приймати підключення. Підключіться через `docker exec -it petrenko-db psql -U postgres -d expenses_petrenko`.

**Очікуваний результат:** контейнер працює (`docker ps`), `psql` всередині контейнера підключається до бази `expenses_petrenko`.

### Завдання 2. Скрипт ініціалізації

Створіть каталог `init/` з файлом `01_schema.sql` (таблиці `categories` і `expenses` з роботи П3) та `02_data.sql` (ваші реальні витрати). Видаліть контейнер і том та запустіть новий контейнер, додавши параметр:

```bash
-v "$(pwd)/init:/docker-entrypoint-initdb.d"
```

**Очікуваний результат:** після першого запуску таблиці створені й заповнені автоматично; у звіті пояснено, чому скрипти не виконуються вдруге, якщо том уже містить дані.

### Завдання 3. Підключення з Python

Підключіться до бази в контейнері з програм роботи П3 (порт `5433`, пароль зі змінної середовища) і виконайте звіт за категоріями.

**Очікуваний результат:** звіт з контейнерної бази збігається зі звітом з роботи П3.

### Завдання 4. Збереження даних

1. Додайте нову витрату, видаліть контейнер (`docker rm -f petrenko-db`) і запустіть його знову з тим самим томом. Перевірте, що витрата збереглася.
2. Повторіть сценарій **без** параметра `-v` і порівняйте результат.

**Очікуваний результат:** з томом дані зберігаються після видалення контейнера, без тому — зникають; у звіті таблиця порівняння двох сценаріїв.

### Завдання 5. Резервна копія

Зробіть резервну копію бази командою `docker exec petrenko-db pg_dump -U postgres expenses_petrenko > backup.sql`, видаліть таблицю `expenses` і відновіть її з копії.

**Очікуваний результат:** після відновлення кількість рядків і сума витрат такі самі, як до видалення.
