# 10. (П5) Тестування програм, що працюють з PostgreSQL, за допомогою pytest

## Мета роботи

- **Освітня (навчальна):** навчитися писати тести для коду доступу до бази даних, готувати тестову базу фікстурами `pytest`, ізолювати тести один від одного транзакціями та перевіряти помилкові сценарії.
- **Дослідна (розвиваюча):** розвинути вміння відокремлювати код роботи з даними від решти програми, щоб його можна було протестувати.
- **Виховна (патріотична):** сформувати професійну звичку ніколи не експериментувати з робочими даними — тести працюють лише з окремою тестовою базою.

!!! danger "Персоналізація обовʼязкова"
    Тестується **ваш** код з робіт П2–П4, а тестові дані — фрагмент ваших реальних витрат.

## Хід роботи

### Завдання 1. Модуль repository.py

Перенесіть код роботи з таблицею `expenses` у функції, що приймають підключення першим параметром:

1. `add_expense(conn, spent_on, category, amount, comment="")` — повертає `id` нового запису (`RETURNING id`).
2. `get_expense(conn, expense_id)` — повертає словник або `None`.
3. `update_amount(conn, expense_id, amount)` — повертає кількість змінених рядків.
4. `delete_expense(conn, expense_id)` — повертає кількість видалених рядків.

**Очікуваний результат:** функції не створюють підключення самостійно і не викликають `print`.

### Завдання 2. Фікстури

Файл `tests/conftest.py`. Створіть фікстуру, що підключається до тестової бази, створює таблицю і **відкочує** всі зміни після кожного тесту:

```python
import os

import psycopg2
import pytest


@pytest.fixture
def conn():
    connection = psycopg2.connect(dbname=os.environ["PGDATABASE_TEST"])
    with connection.cursor() as cur:
        cur.execute(
            """
            CREATE TABLE IF NOT EXISTS expenses (
                id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
                spent_on DATE NOT NULL,
                category TEXT NOT NULL,
                amount NUMERIC(10, 2) NOT NULL CHECK (amount > 0),
                comment TEXT
            )
            """
        )
    yield connection
    connection.rollback()  # жоден тест не залишає даних
    connection.close()
```

**Очікуваний результат:** після запуску всіх тестів таблиця тестової бази порожня.

### Завдання 3. Тести CRUD

Файл `tests/test_repository.py`. Напишіть щонайменше чотири тести:

1. Додавання й читання запису — дані збігаються.
2. Оновлення суми — функція повертає `1`, нова сума збережена.
3. Видалення — після видалення `get_expense` повертає `None`.
4. Від’ємна сума — генерується `psycopg2.errors.CheckViolation` (`pytest.raises`).

**Очікуваний результат:** `pytest -v` показує чотири успішні тести; кожен тест можна запустити окремо і в будь-якому порядку.

### Завдання 4. Параметризація реальними даними

**Очікуваний результат:** п’ять окремих тестів з параметрами в назві; робоча база `expenses_<прізвище>` не змінилася (перевірте кількість рядків до і після).
