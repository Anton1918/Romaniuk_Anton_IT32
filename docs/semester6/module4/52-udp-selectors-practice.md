## Хід роботи

### Завдання 1. Простий UDP ехо-сервер

Файл `udp_server.py`:

```python
import selectors
import socket

PORT = 9507  # 9500 + ваш номер у списку

selector = selectors.DefaultSelector()
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind(("127.0.0.1", PORT))
sock.setblocking(False)
selector.register(sock, selectors.EVENT_READ)
print(f"udp echo on {PORT}")

while True:
    for key, _ in selector.select():
        data, address = key.fileobj.recvfrom(4096)
        print("from", address, data)
        key.fileobj.sendto(b"[petrenko] " + data, address)
```

**Очікуваний результат:** сервер відповідає на кожне повідомлення `nc -u`, а в простої процес сервера не навантажує процесор (перевірте `top`).

### Завдання 2. UDP-клієнт

Файл `udp_client.py`. Клієнт надсилає 5 повідомлень з вашими даними, чекає на кожну відповідь не більше 1 с (`settimeout(1)`) і рахує втрачені відповіді.

**Очікуваний результат:** при працюючому сервері втрат немає; при зупиненому — клієнт не зависає, а повідомляє про 5 втрачених відповідей.

### Завдання 3. TCP і UDP в одному селекторі

Файл `dual_server.py`. Зареєструйте в одному селекторі TCP-сервер з роботи П22 (порт `9000 + N`) і UDP-сервер (порт `9500 + N`). Для кожного сокета збережіть у `data` функцію-обробник (`selector.register(sock, EVENT_READ, data=handler)`) і викликайте її з `key.data`.

**Очікуваний результат:** обидва протоколи обслуговуються одним циклом в одному потоці; клієнти TCP і UDP працюють одночасно.

### Завдання 4. Межі повідомлень

Надішліть TCP-серверу і UDP-серверу три повідомлення поспіль без пауз і порівняйте, скільки разів спрацювали `recv` і `recvfrom` на сервері.

**Очікуваний результат:** у звіті пояснено, чому UDP зберігає межі датаграм, а TCP передає потік байтів, який може об’єднати кілька повідомлень.
