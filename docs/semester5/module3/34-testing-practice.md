## Хід роботи

### Завдання 1. Модуль з функціями

Файл `expenses.py` містить три функції без `print` — лише повернення результату:

1. `parse_line(line)` — приймає рядок `2026-09-21;food;85.50;lunch` і повертає словник `{"date": "2026-09-21", "category": "food", "amount": 85.5, "comment": "lunch"}`. Для рядка з неправильною кількістю полів або нечисловою сумою генерує `ValueError`.
2. `total_by_category(records)` — приймає список словників і повертає словник `{category: total}`, суми округлені до двох знаків.
3. `load_expenses(path)` — читає файл, пропускає коментарі та порожні рядки і повертає список словників.

**Очікуваний результат:** `python3 -c "import expenses"` нічого не виводить, а функції повертають дані, а не друкують їх.

### Завдання 2. Перші тести з assert

Файл `test_expenses.py`. Напишіть щонайменше три тести для `parse_line`:

```python
from expenses import parse_line


def test_parse_line_valid():
    record = parse_line("2026-09-21;food;85.50;lunch")
    assert record["category"] == "food"
    assert record["amount"] == 85.5
```

Запустіть `pytest -v` і переконайтеся, що всі тести зелені. Потім навмисно зламайте функцію (наприклад, поверніть суму як рядок) і покажіть, що тести це виявили.

**Очікуваний результат:** у звіті два виводи `pytest -v`: усі тести пройдено та тест, що впав, з повідомленням `AssertionError`.

### Завдання 3. Перевірка винятків

Додайте тести, що перевіряють генерацію `ValueError` для некоректних рядків:

```python
import pytest

from expenses import parse_line


def test_parse_line_bad_amount():
    with pytest.raises(ValueError):
        parse_line("2026-09-21;food;abc;lunch")
```

Перевірте щонайменше два різні види помилок: неправильна кількість полів і нечислова сума.

**Очікуваний результат:** тести проходять, а якщо у функції прибрати генерацію винятку, вони падають з повідомленням `DID NOT RAISE`.

### Завдання 4. Параметризований тест

За допомогою `@pytest.mark.parametrize` перевірте `parse_line` на 5 рядках з вашого файлу витрат: для кожного рядка вкажіть очікувану категорію та суму.

**Очікуваний результат:** `pytest -v` показує 5 окремих тестів з різними параметрами в назві.

### Завдання 5. Тест з тимчасовим файлом

Перевірте `load_expenses` і `total_by_category` на тимчасовому файлі, створеному фікстурою `tmp_path`:

```python
from expenses import load_expenses, total_by_category


def test_total_by_category(tmp_path):
    path = tmp_path / "expenses.csv"
    path.write_text(
        "# date;category;amount;comment\n"
        "2026-09-21;food;85.50;lunch\n"
        "\n"
        "2026-09-22;food;14.50;coffee\n",
        encoding="utf-8",
    )
    totals = total_by_category(load_expenses(path))
    assert totals == {"food": 100.0}
```

Додайте ще один тест, що перевіряє `total_by_category` на вашому справжньому `data/expenses.csv`: очікувані суми візьміть з результату роботи 22.

**Очікуваний результат:** обидва тести проходять, а тимчасовий файл не залишається в каталозі `lab34`.
